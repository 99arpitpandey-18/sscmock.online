01

Database, DBMS और ACID Properties

🔹 Database (DB) क्या है?

Database, organized data का एक systematic collection है जिसे electronically store, manage और retrieve किया जा सकता है। यह real-world entities (जैसे students, employees, products) का structured representation है।

🔹 DBMS (Database Management System) क्या है?

DBMS, software है जो database के creation, maintenance और manipulation को manage करता है। यह data और user/application के बीच interface का काम करता है।

  • Examples: MySQL, Oracle, PostgreSQL, Microsoft SQL Server, MongoDB (NoSQL)।
  • Advantages over File System: Data Redundancy control, Data Consistency, Data Security, Backup & Recovery, Concurrent Access (Multi-user)।

🔹 DBMS के Types (Exam Focus)

  • Relational DBMS (RDBMS): Data को tables (relations) में store करता है। SQL का उपयोग। (MySQL, Oracle)।
  • NoSQL DBMS: Non-relational, flexible schema। Document-based (MongoDB), Key-Value (Redis), Column-family (Cassandra), Graph (Neo4j)।
  • Object-Oriented DBMS: Data को objects के रूप में store करता है। (ObjectDB)।

🔹 ACID Properties (बहुत महत्वपूर्ण)

ACID, transaction properties का एक set है जो database transactions की reliability सुनिश्चित करता है:

  • Atomicity (अणुशीलता): Transaction या तो पूरी तरह से execute होता है या बिल्कुल नहीं (All-or-Nothing)।
  • Consistency (संगतता): Transaction database को एक valid state से दूसरी valid state में लाता है (Integrity constraints maintained)।
  • Isolation (पृथकता): Concurrent transactions एक-दूसरे को affect नहीं करते (Serializability)।
  • Durability (स्थायित्व): Committed transaction का data permanent रहता है, system failure के बाद भी।
🎯 DBMS vs File System: DBMS removes redundancy, provides security, and supports concurrent access.
02

Data Models, ER Diagram & Architecture

🔹 Data Models (Types)

  • Hierarchical Model: Tree-like structure (Parent-Child). (Old – IMS)।
  • Network Model: Graph structure (Many-to-Many relationships)।
  • Relational Model (RDBMS): Table-based (Rows/Tuples और Columns/Attributes)। Most popular।
  • Object-Oriented Model: Objects with methods।

🔹 ER (Entity-Relationship) Model

ER Model database design का conceptual framework है।

  • Entity: Real-world object (जैसे Student, Employee)। Represented by Rectangle.
  • Attribute: Entity की properties (जैसे Name, Age, ID)। Represented by Ellipse.
    Types: Simple (atomic), Composite (split into sub-parts, e.g., Address), Derived (calculated, e.g., Age from DOB), Multi-valued (e.g., Phone numbers)।
  • Relationship: Entities के बीच association (जैसे Student Enrolls in Course)। Represented by Diamond।
    Cardinality: One-to-One (1:1), One-to-Many (1:M), Many-to-Many (M:M)।
    Participation: Total (double line) vs Partial (single line)।

🔹 Database Architecture (3-level Schema)

  • External Level (View Level): End-user का view। Multiple views possible।
  • Conceptual Level (Logical Level): Database का overall structure। Tables/Relations।
  • Internal Level (Physical Level): Storage structure, indexing, file organization।

Data Independence: Ability to change schema at one level without affecting higher levels. (Logical Independence – change conceptual without affecting external; Physical Independence – change internal without affecting conceptual)।

🎯 ER Concepts: Rectangle = Entity, Ellipse = Attribute, Diamond = Relationship. 1:M is most common.
03

Keys (Primary, Foreign) & Normalization

🔹 Keys in DBMS (बहुत महत्वपूर्ण)

  • Super Key: Columns (or combination) का set जो uniquely identify each row करता है। (Contains extra columns)
  • Candidate Key: Minimal Super Key (no redundant columns). Super Key का subset जो unique है।
  • Primary Key: एक unique Candidate Key जो table को identify करता है।
    Rules: Unique, Not Null, Immutable (ideally), Only one per table।
  • Alternate Key: Candidate keys जो Primary Key नहीं हैं।
  • Foreign Key: दूसरी table के Primary Key को reference करता है।
    Rules: Values can be duplicated, can be NULL. Referential Integrity सुनिश्चित करता है।
  • Composite Key: दो या अधिक columns का combination जो Primary Key के रूप में use होता है।

🔹 Normalization (Anomalies को remove करना)

Normalization, data redundancy और anomalies (Insertion, Deletion, Update) को reduce करने के लिए tables को decompose करने की प्रक्रिया है।

  • 1NF (First Normal Form): Each cell में एक single atomic value (no multi-valued attributes)।
  • 2NF (Second Normal Form): 1NF + No Partial Dependency (No non-prime attribute dependent on part of Candidate Key) – applicable only for Composite Keys.
  • 3NF (Third Normal Form): 2NF + No Transitive Dependency (No non-prime attribute dependent on another non-prime attribute).
  • BCNF (Boyce-Codd Normal Form): 3NF का stricter version. For every functional dependency X → Y, X must be a Super Key.
  • 4NF & 5NF: Multi-valued dependencies और Join dependencies से deal करती हैं (less frequent in exams)।
🎯 Key Tricks: Primary = Unique + Not Null. Foreign = References Primary Key of another table. 2NF = No partial dependency. 3NF = No transitive dependency.
04

SQL – Commands, Queries & Joins

🔹 SQL (Structured Query Language) – Types

  • DDL (Data Definition Language): Database structure को define/alter करना।
    Commands: CREATE, ALTER, DROP, TRUNCATE, RENAME।
  • DML (Data Manipulation Language): Data को manipulate (insert, update, delete)।
    Commands: INSERT, UPDATE, DELETE, SELECT (some consider SELECT separately)।
  • DCL (Data Control Language): Permissions/access को manage करना।
    Commands: GRANT, REVOKE।
  • TCL (Transaction Control Language): Transactions को manage करना।
    Commands: COMMIT, ROLLBACK, SAVEPOINT।

🔹 Important SQL Clauses & Keywords

  • SELECT: Data retrieve करना। (e.g., SELECT * FROM Students;)
  • WHERE: Conditions filter करना। (e.g., WHERE age > 18)
  • GROUP BY: Similar data को group करना। (Often with Aggregate functions – COUNT, SUM, AVG, MAX, MIN)
  • HAVING: Groups पर conditions लगाना। (e.g., HAVING COUNT(*) > 5)
  • ORDER BY: Sorting (ASC/DESC)।
  • DISTINCT: Unique values लाना।
  • LIKE: Pattern matching (% for any sequence, _ for single character)।
  • JOINS: Multiple tables से data combine करना।
    INNER JOIN: Matching rows only।
    LEFT/RIGHT JOIN: All rows from left/right table + matches।
    FULL JOIN: All rows from both tables।
    SELF JOIN: Table का अपने साथ join।

🔹 DDL vs DML – Key Difference

DDL (CREATE, ALTER, DROP): Auto-commit होता है (permanent)। Structure बदलता है। DML (INSERT, UPDATE, DELETE): Manual commit (COMMIT/ROLLBACK) की आवश्यकता होती है। Data बदलता है, structure नहीं।

DROP vs TRUNCATE vs DELETE: DROP removes structure, TRUNCATE removes all data (faster, resets auto-increment), DELETE removes selected data (slower, can be rolled back)।

🎯 SQL Query Order (Logical): SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY.
05

Transactions, Concurrency & Deadlock

🔹 Transaction क्या है?

Transaction, database operations का एक logical unit है जो एक साथ execute होते हैं (e.g., Bank Transfer: Debit + Credit)।

Transaction States: Active (executing) → Partially Committed (last statement done) → Failed (error) / Committed (success) → Aborted (rolled back)।

🔹 Concurrency Issues (Problems)

जब multiple transactions concurrently execute होती हैं, तो ये problems आ सकती हैं:

  • Lost Update (Lost & Write): Two transactions update same data, one update overwrites the other.
  • Dirty Read (Uncommitted Dependency): Transaction reads data written by an uncommitted transaction.
  • Unrepeatable Read (Inconsistent Analysis): Transaction reads same row twice and gets different data (because another transaction updated it in between).
  • Phantom Read: Transaction re-executes a query and gets different set of rows (because another transaction inserted/deleted in between).

🔹 Concurrency Control Protocols

  • Locking:
    • Shared Lock (S-Lock): Read-only (multiple transactions can hold simultaneously)।
    • Exclusive Lock (X-Lock): Write (only one transaction can hold)।
  • Two-Phase Locking (2PL): Growing phase (acquire locks) and Shrinking phase (release locks)। Strict 2PL (releases locks after commit) ensures recoverability.
  • Timestamp-based Protocols: Assigns timestamp to transactions; ensures conflict serializability.
  • Serializability: Schedule का result concurrent transactions के किसी serial order के equal होना।

🔹 Deadlock

Deadlock, condition जब दो या अधिक transactions एक-दूसरे के held resources की wait करते हैं और आगे नहीं बढ़ते।

Conditions for Deadlock: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait।

Deadlock Handling: Prevention (remove any condition), Detection (wait-for graph), Recovery (abort one transaction)।

🎯 Transaction Concepts: Lost Update = Overwrite, Dirty Read = Uncommitted data, Phantom = New rows. 2PL prevents conflicts. Deadlock = Circular wait.
